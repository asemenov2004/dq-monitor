# Веб-интерфейс

Интерфейс на FastAPI и Jinja использует то же ядро и ту же базу `meta`, что CLI и Airflow.
Восемь типов проверок настраиваются через формы. Правила можно изменять и выключать:
история результатов и инцидентов сохраняется.

## Запуск

Из корня репозитория, при запущенном Docker:

```bash
docker compose -f compose.yaml -f compose.web.yaml up -d --build
```

Открыть http://localhost:8000. Init-сервис применяет миграции под общей блокировкой
с init-сервисом Airflow. Данные полигона эта команда не создаёт и не сбрасывает.

Для запуска Python без контейнера:

```bash
pip install -e '.[web,dev,stand]'
python -m dq_monitor.meta.migrate
uvicorn dq_monitor.web.app:create_app --factory --host 127.0.0.1 --port 8000 --workers 1
```

## Что нажимать

1. **Обзор** показывает последний сохранённый результат активных правил. `FAIL` означает
   нарушение данных, `ERROR` означает ошибку выполнения. `SKIP` и ещё не запущенные
   проверки показаны отдельно: разогрев не считается успешной проверкой.
2. Для существующего TPC-H нажать **Время полигона**, затем **Запустить активные**.
   Первая кнопка только читает часы. Вторая выполняет ядро и открывает отчёт прогона.
   Дождаться ответа: общий lock защищает от пересечения с CLI и Airflow.
3. **Проверки → Создать проверку**: выбрать таблицу и тип, заполнить параметры.
   Например, `not_null`, столбец `o_custkey`, допустимая доля `0`, область `batch`.
   Cron задаётся пятью полями UTC. Пустое расписание означает каждый тик Airflow.
4. Открыть карточку: график последних 100 результатов, параметры, история и инциденты.
   По горизонтали логическое время UTC; повторные запуски с одной датой имеют одну
   координату. Числа разогрева отображаются, пропуски не соединяются.
5. **Изменить** сохраняет новое правило; **Выключить** исключает его из следующих
   прогонов. Старые результаты остаются снимками прежних выполнений.
6. **Источники** регистрирует подключения и таблицы. В форме указывается имя переменной
   с паролем, например `POSTGRES_PASSWORD`; сам пароль хранится в окружении/`.env`.
   Кнопка проверки подключения выполняет только `SELECT 1`.

Для первой подготовки полигона см. README. Регулярные запуски настраиваются через
[Airflow](airflow.md); на историческом полигоне для демонстрации используется ручной
запуск с модельным временем, а не реальное время планировщика.

## Границы MVP

Один пользователь, один процесс web, доступ на loopback. Авторизация и роли не входят
в этот локальный MVP. Формы защищены CSRF, текст экранируется Jinja, скрипты и стили
поставляются внутри пакета без CDN. Это приложение для локальной демонстрации;
публикация в сеть потребует отдельного решения об авторизации и HTTPS.

Функциональные требования зафиксированы в [mvp-requirements.md](mvp-requirements.md).
