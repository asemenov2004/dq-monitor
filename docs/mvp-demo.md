# Шпаргалка демонстрации MVP

Команды для Git Bash, из корня проекта. Docker Desktop должен быть запущен.
Для уже подготовленного полигона генерация и сброс TPC-H не нужны.

## 1. Запуск

```bash
cd "/c/Documents/4 курс/Диплом/dq-monitor"
source .venv/Scripts/activate
pip install -e '.[web,dev,stand]'
python scripts/mvp.py up --airflow
```

Что делает: собирает приложение, применяет миграции, запускает PostgreSQL, веб,
почтовый ящик Mailpit, Mattermost, worker доставки и Airflow. В `.env` сохраняет
локальные секреты Mattermost, включает доставку. Повторный запуск сохраняет данные.
Первая сборка и загрузка образов занимают несколько минут.

Открыть четыре вкладки:

| Вкладка | Адрес | Вход |
| --- | --- | --- |
| Приложение | http://localhost:8000 | Не нужен, локальный MVP |
| Почта | http://localhost:8025 | Не нужен |
| Mattermost | http://localhost:8065 | `dqadmin`, пароль `MATTERMOST_ADMIN_PASSWORD` из `.env` |
| Airflow | http://localhost:8081 | `admin`, пароль `AIRFLOW_ADMIN_PASSWORD` из `.env`, default `airflow_local_password` |

В Mattermost открыть команду DQ Monitor, канал «Оповещения DQ» (`alerts`).
В Airflow показать DAG `dq_monitor_checks`. На историческом TPC-H оставлять его
на паузе: расписание использует реальные часы, а данные относятся к 2025 году.
Ручной Trigger допускает параметр `logical_now` из `python -m dq_stand status`.

## 2. Подготовить маленький пример

```bash
python scripts/demo.py prepare
python scripts/demo.py run
```

Что делает: создаёт **отдельную** `warehouse.dq_demo.orders` с 10 заказами и
проверку `demo_amount_not_null`. Повторный prepare заново заполняет только эту
демонстрационную таблицу. Команда run запускает одну проверку через HTTP-интерфейс.

Ожидается PASS, доля NULL = 0. В терминале появятся ссылки на отчёт и карточку.
Открыть карточку: показать параметры, график, историю. В UI можно создать такую
проверку самостоятельно: тип not_null, столбец amount, scope table, порог 0.

## 3. Испортить две суммы

```bash
python scripts/demo.py break
python scripts/demo.py run
```

Что делает: заменяет `amount` двух заказов на NULL и выполняет проверку ещё раз.
Ожидается FAIL, наблюдение 0.2, один открытый инцидент. Открыть «Инциденты» и
«Уведомления». В течение обычных 5 секунд появятся письмо в Mailpit и сообщение
в канале Mattermost. Оба содержат номер того же инцидента.

## 4. Показать отсутствие лишних сообщений

```bash
python scripts/demo.py run
```

Ожидается снова FAIL. Номер инцидента остаётся прежним. Нового сообщения об
открытии нет: очередной запуск подтверждает существующую проблему.

## 5. Восстановить данные

```bash
python scripts/demo.py repair
python scripts/demo.py run
```

Что делает: возвращает две исходные суммы. Ожидается PASS; тот же инцидент
закрывается. В почту и Mattermost приходит по сообщению о восстановлении.
В журнале всего четыре отправки на этот инцидент: два события × два канала.

В этом примере порча задаётся командой для демонстрации. Полноценный инжектор
размеченных дефектов и статистический эксперимент остаются этапом 8.

## 6. Показать большой полигон и аномалии

Открыть обзор и нажать **Время полигона → Запустить активные**. Это ручной
прогон уже загруженной партии, без догрузки и изменения TPC-H. В карточке
`orders_volume_anomaly` показать параметры окна и диагностику SKIP разогрева.
Повторные прогоны одного модельного дня не заменяют историю предыдущих дней.
Разогретый статистический детектор отдельно проверен при приёмке этапа 4;
на рабочей истории MVP не надо выдавать SKIP за обнаруженную аномалию.

Для короткой демонстрации самого детектора без догрузки TPC-H:

```bash
python scripts/accept_anomaly.py --report "../Артефакты ВКР/MVP_аномалии.json"
```

Создаёт отдельное правило средней `amount` с окном 7 дней на той же маленькой
таблице. Через настоящий HTTP выполняет семь дней разогрева, увеличивает две суммы
в десять раз, получает FAIL, восстанавливает суммы и получает PASS. После показа
правило выключается; его карточка и график остаются в списке проверок. Каждый новый
показ использует следующие модельные даты, чтобы история предыдущего не мешала.
Сценарии на маленькой таблице выполняются последовательно, а не одновременно.

## 7. Автоматическая приёмка того же сценария

```bash
python scripts/accept_mvp.py --report "../Артефакты ВКР/MVP_приёмка.json"
```

Команда выполняет шаги 2–5, проверяет БД, настоящие HTTP-отчёты, два письма через
Mailpit API и два сообщения через Mattermost API. Сохраняет номера, времена и
результаты без паролей. Даже при ошибке возвращает демонстрационные суммы.
Это интеграционная приёмка, не исследовательский эксперимент precision/recall.

## Проверить состояние и остановить

```bash
python scripts/mvp.py status --airflow
python scripts/mvp.py stop --airflow
```

Stop останавливает контейнеры, тома с данными сохраняются.

Для SQL-клиента: host `localhost`, port `5433`, user `dq`, password из
`POSTGRES_PASSWORD` в `.env` (локальный default `dq_local_password`).
Базы `warehouse` и `meta`; таблицы приложения находятся в `meta.public`.
