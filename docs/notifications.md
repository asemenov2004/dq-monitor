# Уведомления: почта и Mattermost

MVP использует почту и локальный корпоративный мессенджер Mattermost. Выбор и
альтернативы разобраны в [messengers.md](messengers.md).

## Когда создаётся сообщение

Первый `FAIL` открывает инцидент. В той же транзакции в `notification` записываются
два сообщения об открытии: `email` и `mattermost`. Повторный `FAIL` продолжает тот
же инцидент и новых сообщений не добавляет. Первый `PASS` закрывает инцидент и
ставит ещё два сообщения о восстановлении. `ERROR` и `SKIP` состояние не меняют.
Старые инциденты при миграции автоматически не рассылаются.

Это transactional outbox: сначала сохраняется факт, потом отдельный worker делает
сетевой запрос. Ни SMTP, ни webhook не вызываются из runner. Поэтому недоступность
мессенджера не превращает успешно выполненную проверку в ошибку выполнения.

Сообщение содержит номер инцидента, проверку, таблицу, важность, логическое время
и результат. Текст сохраняется снимком: последующее редактирование правила его
не меняет. Уникальность `(incident_id, channel, event)` защищает от повторной
постановки одного события в очередь.

## Локальная доставка

```bash
python scripts/mvp.py up
```

Команда генерирует секреты в `.env`, включает `NOTIFY_ENABLED`, поднимает Mailpit,
Mattermost и worker. Создаёт администратора, команду `dq-monitor`, канал `alerts`
и incoming webhook. При повторном запуске использует существующие объекты. Полигон
и историю проверок не сбрасывает.

- http://localhost:8025: принятые письма Mailpit, без входа.
- http://localhost:8065: Mattermost. Пользователь из `MATTERMOST_ADMIN_USERNAME`
  (по умолчанию `dqadmin`), пароль из `MATTERMOST_ADMIN_PASSWORD` в локальном `.env`.
- http://localhost:8000/notifications: состояние очереди и число попыток.

Mailpit принимает настоящие SMTP-сообщения, но не пересылает их в интернет.
Адрес `demo@example.test` является адресатом демонстрации. Проверяется доставка
до SMTP-сервиса, а не получение письма внешним человеком.

Вне Docker один пакет очереди можно обработать так:

```bash
python -m dq_monitor.notifications.worker --once
```

Без `--once` worker опрашивает очередь каждые 5 секунд. Одновременная работа двух
worker одной базы запрещена advisory lock. Выключенные каналы остаются в очереди,
попытки не расходуются. Локальный Compose направляет SMTP на `mailpit:1025`, webhook
на `mattermost:8065`; с Windows используются localhost:1026 и localhost:8065.

## Повторы и сбои

Перед сетью фиксируется номер попытки и время следующего разрешённого запуска.
После успеха ставятся `sent` и реальное `sent_at`. После ошибки остаётся `failed`
с безопасным описанием без URL, пароля и тела ответа. По умолчанию максимум пять
попыток; задержка 30, 60, 120, 240 секунд, верхняя граница 3600 секунд.

Закрытие ждёт `sent` открытия в том же канале, чтобы уведомление о восстановлении
не пришло первым. Для старого инцидента, у которого сообщения открытия в новом
канале нет, закрытие доставляется самостоятельно. Если имеющееся открытие исчерпало
попытки, закрытие остаётся ожидающим.
Автоматического бесконечного повтора или ручного переотправления через UI нет.
Требуется устранить причину и осознанно восстановить очередь на уровне эксплуатации.

Гарантия доставки **at least once**: если сервис уже принял сообщение, а процесс
упал до сохранения `sent`, возможен дубль. Общей транзакции PostgreSQL с SMTP/HTTP
нет. `sent` означает принятие сообщения сервисом, а не прочтение адресатом.

## Настоящий SMTP

Worker поддерживает `NOTIFY_SMTP_HOST`, `NOTIFY_SMTP_PORT`, `NOTIFY_SMTP_FROM`,
`NOTIFY_SMTP_TO` (адреса через запятую), `NOTIFY_SMTP_USERNAME`, `NOTIFY_SMTP_PASSWORD`,
`NOTIFY_SMTP_STARTTLS` или `NOTIFY_SMTP_SSL`. Одновременно два TLS-режима не задаются.
Секреты остаются в окружении или `.env`. Для настоящего сервера запускают worker
с этими настройками вне локального Compose либо меняют его SMTP-переадресацию.

`NOTIFY_MATTERMOST_WEBHOOK_URL` задаёт incoming webhook; переходы по перенаправлениям
запрещены, HTTPS проверяет сертификат. Историческое значение `telegram` оставлено
в схеме ради совместимости метаданных, отправителя Telegram в этом MVP нет.

Остальные настройки и значения по умолчанию находятся в `.env.example` и
`src/dq_monitor/notifications/settings.py`.
